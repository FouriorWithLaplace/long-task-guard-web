# 页面摘要与低开销读取

页面访问不触发业务数据库扫描、任务恢复或完成度计算。首页、列表、任务页和全选读取已维护的 JSON 文件；详情、图片、导出和任务操作才按需访问业务数据。

## 使用

```powershell
npm run build
npm start
```

开发时使用 `npm run dev`。两个命令都会统一管理页面更新器、采集后台和 Next 进程。Ctrl+C 会通知子进程清理资源；超过 3 秒仍未退出时，只终止本次启动拥有的进程树。不要再单独执行 `next start`，它不会启动采集后台和更新器。

首次运行自动生成摘要；以后启动读取已有文件并补做停机期间发生的变化，不重算全部词条。字段字典或数据库结构改变时才重新生成相关展示数据。原先已停止的采集任务保持停止。

手动修复摘要时，先停止网站，再执行：

```powershell
npm run views:build
npm start
```

这个命令只重建派生展示数据，不清空采集成果或重启采集任务。

更新器使用 `panel/page-views.lock` 防止重复运行。Windows 启动时会核对锁中 PID 的进程名称和创建时间，自动回收进程已退出、系统重启或 PID 已被复用的过期锁；不会结束该 PID 当前对应的其他程序。确有更新器运行时仍拒绝启动第二个实例。新版锁另存随机标识，退出时只移除本次启动创建的锁，并兼容旧版只保存 PID 的格式。

## 文件组织

文件位于 `C:/Users/laplace/Desktop/encyclopedia-agent/panel/page-views/`：

| 文件 | 用途 |
| --- | --- |
| `home.json` | 分类数量、排除数量、活动任务数量 |
| `catalog/<分类>.json` | ID、名称、筛选状态；搜索和跨页全选只读该索引 |
| `entries/<分片编号>.json` | 每 128 个 ID 一片，保存展示字段和预计算进度；列表只读当前页涉及的分片 |
| `task-index.json` | 任务 ID、是否活动和调度字段；任务页每页只返回 30 条摘要 |
| `manifest.json` | 发布版本、源数据变更检查点和格式版本 |

摘要不保存字段原文、证据快照、候选内容或全部任务结果。进程缓存有数量上限；文件没有变化时复用解析结果，相同筛选条件复用匹配结果。

运行任务页可通过“词条分类”选择全部分类或词条库中的具体分类，科学词条包含其子类型。“正在进行”和“全部任务”都先按分类筛选，再计算数量和分页；跨页全选使用同一范围。切换分类会回到第一页并清空选择。`GET /api/encyclopedia/tasks` 和 `events?view=running` 接受 `category=all|book|paper|…`；筛选只关联任务索引和已有分类索引，不扫描数据库或加载所有任务详情。

分类词条页和任务列表提供默认、首字母（中文拼音 / 英文 A–Z）、完成度从高到低三种排序，使用 `sort=default|name|progress` 参数。先筛选、排序，再分页；全选和 SSE 使用同一排序。切换排序回到第一页，保留已选词条。完成度使用已处理字段数 / 可处理字段数，比例相同时按 ID 升序。默认排序保持原有 ID 顺序。摘要格式升级为 3，重启更新器时自动补齐完成度和调度索引；新排序不会读取所有词条详情。

任务页额外提供“执行顺序”（`sort=execution`）：占用执行名额的任务在前，包括保留名额的重试任务；已就绪任务按调度器使用的入队时间、入队序号、ID 排序；未到重试时间、停止和完成的任务在后。页面和调度器共享排序与就绪判断函数。每个等待任务显示全局排队位置，切换分类或翻页不会重新编号。队列变化后随实时摘要更新；选择这个排序只影响查看，不调整实际执行顺序。同时执行数量由全局并发设置控制，占用名额的任务之间并不代表串行执行。

## 更新机制

- 主库安装 `panel_view_*` 变更记录表和触发器。词条、分类归属、字段值、字段字典发生变化时，在原事务内记录受影响的 ID。其他程序通过正常 SQLite 写入同样会触发，回滚的事务不会留下变更记录。
- 任务库安装 `panel_task_changes` 和任务触发器。正常任务写入在同一事务更新轻量任务摘要；外部程序直接修改任务时，由更新器根据变更记录补齐摘要。
- 更新器监听数据库文件变化，将短时间内的变化合并，通常约 250ms 后处理。每 5 秒有一次轻量检查，用于补偿丢失的文件系统通知；无变化时不重新计算或写摘要。
- 只重新读取受影响的词条。仅任务状态变化时，复用文件中已有的字段填充计数，不读取业务字段。未受影响的分片不重写；分类索引和首页统计没有变化时也不重写。
- 先用临时文件加重命名发布完整 JSON，再发布 manifest，最后确认变更记录。中途退出后，未确认的变更会重放。跨库写入和页面更新是最终一致的，通常有几百毫秒延迟，不把它用于提交权限判断。
- SSE 只发送当前页面需要的数据。首页不接收全部任务，分类页不接收其他页内容，详情仅在对应词条变化后刷新；心跳不读取业务数据库。

数据库替换、手工删除触发器或摘要损坏后，应停止网站并运行 `npm run views:build`。不要只拷贝带有 WAL 写入的主数据库文件来替换数据库；应使用正常 SQLite 备份或完整迁移流程。

## 执行与正确性

采集后台单独运行在受监督的本地进程中，只接受启动器生成的随机令牌。网页重操作代理到后台，后台忙碌不会阻塞首页、分页和全选。提交核对、服务租约、代次检查、停止后的迟到回调保护继续保留。

后台调度只查询轻量摘要，仅在实际执行某个任务时读取其完整结果。同一轮批量操作的调度和通知会合并；已完成或已经运行的批量项目先通过摘要跳过。批量请求仍按 50 条提交，页面会显示逐条处理结果；整批发送完成前仍需保持页面打开。

业务导出保留原有业务结构，排除仅供本机页面更新使用的 `panel_view_*` 对象及其自增记录。

## 验证

### 修改统计规则时的交付约束

- 详情读取业务数据库及任务本体；总览读取 `entries/*.json`、分类索引和任务索引。修改进度规则时，必须同时检查这两条路径，不能把详情正确当作总览已更新。
- 程序字段以字段字典的 `collection_mode=system` 标记为准，不计入已填充、已处理及两者的总数，也不显示在任务详情中。数据库中的字段、值和标记保留。
- 统计口径变化必须提供已有摘要的迁移或重建机制。数据库没有新写入时，旧摘要也必须能升级；只修改源码不会更新已经加载代码的后台进程。
- 回归测试必须从旧任务范围、旧摘要文件开始，验证重建后的计数、完成状态、排序和筛选一致，同时保留资料核查结果与证据。
- 报告“已修复”前，要对同一个实际词条比较详情接口、总览接口和磁盘摘要；确认运行中的更新器已加载新代码。若尚未重启或重建，明确说明尚未生效，不能只以单元测试通过作为线上修复依据。
- 排查同步问题必须先记录实际差异及版本、检查点、进程信息，再确认根因。不得仅凭代码阅读推断某个调用顺序就是根因；变更记录必须在对应展示文件成功发布后才确认，发布期间的新写入必须留待下一轮处理。

`npm test` 包含数据库不可用时的纯文件读取、分页与选择一致性、外部修改、无变化不重写、只更新对应分片、事务回滚、删除、字段字典变化，以及发布中断后重放的测试。测试使用隔离数据库，不启动真实采集。

本机改造后的实测：重复请求首页、分类列表、任务页约 7～12ms；浏览器跨页选中 741 条书籍约 39ms、选中 3,900 条论文约 57ms。空闲 5 秒采样中，网页和更新器没有可测 CPU 时间增量，后台约消耗 0.016 秒 CPU 时间。系统计时有精度限制，这不表示绝对零消耗。

当前 29,863 条词条的首次摘要构建约 16.5 秒；已有摘要且无变更时，启动检查约 37ms。生产构建和 180 项测试通过，Ctrl+C 后端口与子进程释放，并验证了同端口重启。耗时受磁盘缓存、电脑负载和数据规模影响，这些是测量结果，不是固定保证。
