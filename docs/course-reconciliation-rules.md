## 阶段一：清单核对、原件登记与建档

由具有课程目录维护能力的独立任务执行。当前工作台只有 `entry_context`、`entry_source`、`submit_field`、`save_note`、`finish_task`；它们不能新增实体、软删除实体或登记原件。**只编辑本规则或点击现有词条“开始”，不能完成本阶段。**没有对应维护能力时输出变更清单并报告能力缺口，不让单词条采集模型绕过工具写库。本规则不要求现在增加应用代码。

### 1. 固定完整来源清单

对上表每门课程保存 source_key、原名、课程版本／快照、远端主机与绝对路径、目录文件、正文清单、字节数、SHA-256、读取日期、测试／生成声明及本地目标位置。记录每个文件的 expected、available 状态，保留目录顺序。JSON 与 MD 的标题、讲次有冲突时记录双方证据。

网络断开、权限失败、路径迁移、正文缺失、文件只含占位内容，都是来源核验失败；**不是课程应该删除的证据**。无法核验完整允许清单时不执行批量软删除，也不宣称分类整理完成。不要仅凭 README、空目录、JSON 条目创建“正文齐全”的课程。

将明确文件下载到本机原件根下的专用课程目录，下载临时文件校验后再登记。文件真实路径必须位于 dataRoot 内，避免同名覆盖和链接越界。原件只读保存，不为填字段修改正文；发现错误另记说明。保留实际正文、对应目录 JSON、来源说明及逐文件哈希；不下载整个远端数据库。

### 2. 对账与身份匹配

只读检查维护库标记、实际 schema、字段字典、同步触发器、原件关联和已有身份键。查询当前全部 lecture 词条，包括软删除、excluded 和未展示项；跨分类只读查重，不自动改分类。

匹配优先级为：已有相同来源稳定键 → 来源 ID／课程 slug／field 与资料版本及所属课程一致 → 原件路径或哈希结合来源关系 → 标题与正文证据共同确认。名称相近、同一教材、同一学科、同名章节、共享某份讲稿都不构成课程相同的充分条件。禁止仅用 LIKE 或标题相似度执行删除、合并。

输出逐项对账清单，包含 action、source_key、entity_id（新建时 null）、现名、目标名、身份依据、原件清单、旧版本／更新时间、原因、未决事项。动作定义：

| action | 含义 |
| --- | --- |
| keep | 一门允许课程与一个现有未删除词条明确对应，保留实体 ID 和现有证据。 |
| create | 允许课程正文已验证且未发现对应实体，建立最小课程档案，后续由采集工具填字段。 |
| soft_delete | 当前 lecture 词条经核对不属于允许清单；或有充分同课证据的冗余词条。保留原数据及审计。 |
| review | 身份不明、跨分类冲突、来源不完整、候选重复主体不明或此前删除／排除原因不清。暂不变更该实体，明确需要解决的问题。 |

同课已有删除记录时先查历史原因，不盲目新建或清除 deleted_at；明确属于本批目录调整且可恢复时，由维护任务记录恢复动作及依据。其他删除、排除原因未解决的留 review。已有独立课次与完整课程的关系确认后，先归档其来源和关联，再按本批粒度规则标记旧课次删除，不能直接把单讲原 ID 改名为整课。

### 3. 提交维护变更

执行时重新核对旧版本和删除状态，使用现有维护写入机制及任务门禁。受影响课程若有排队、运行或未确认写入，先协调停止及提交核对；不让删除和字段写入竞态发生。使用 SQLite 一致性备份或现有快照机制，不只复制活动数据库主文件。保存可回滚的旧值、原件关联和批次清单。

- **软删除**：以 `entities.deleted_at` 的实际时间戳为删除标记，同时关闭 `display_enabled` 和 profile 的 `is_presentable`，记录原因及批次审计；其他状态依现有维护约定同步。不要物理 DELETE、删原件、级联清除证据，或只写 `state='excluded'` 冒充删除。已删除记录重复执行保持原删除时间和原因。保留关系端点历史，展示及检索侧过滤已删主体。
- **新建**：数据库分配新 entity_id，通过既有初始化机制创建 entities、wiki_articles、wiki_entry_profiles 和 wiki_type_lecture 的一致记录；检查实际约束、触发器及身份表后操作。不要只插一张表，不伪造远端 ID，不覆盖既有实体。不先生成所有业务字段；设置 pending、不可展示及对应维护状态，不沿用 published 默认值。
- **原件登记**：将已验证正文登记到 `wiki_original_documents`，保存真实 sha256、size、dataRoot 内相对 blob_path，再经 `wiki_entry_files` 关联课程。课程 JSON、来源清单按真实角色登记为原件或来源快照；来源证据可通过 `wiki_evidence_sources`／`wiki_entry_evidence` 关联。实际填法遵从现有导入器和约束，不编造 public URL。
- **同步与幂等**：固定列表、profile JSON、字段类型元数据、修订、展示摘要、搜索索引按现有约定同步。稳定来源键避免重复建档，原件按哈希查重；事务回滚或重试不增加重复课程、重复关联或重复删除审计。提交不明先查批次和实际结果，不盲目重放。

完成后回读每个动作和关联原件，检查外键及同课唯一性。完成状态要求：允许清单的 12 门课程各有唯一未删除 lecture 档案且原件可读；其他 lecture 已按明确对账结论软删除；review 为零。若尚有 review，报告部分完成而不强凑 12 条。不要改动其他分类的数据来达成数量。

### 当前数据库的字段映射

字段名、实际类型、采集规则及可写性以 `entry_context` 从当前数据库读取的定义为准。下面仅说明已存在字段的使用方式；执行时仍须核对字段是否存在和可写。历史文档中的新增字段建议不作为提交或迁移依据，程序导出的 Markdown 也不能反向覆盖数据库定义。

| 现有字段 | 填写规则 |
| --- | --- |
| fields.resource_type | Bohrium 为 knowledge_field；Velo 为 course。标记课程组织形式，不把生成模型当作者。 |
| sections.overview | 根据课程声明和正文整理范围、对象及内容简介，标明“整理”，保留测试／AI 生成背景，不冒充原文摘要。 |
| fields.syllabus | JSON 保存课程目录与课次结构，保留稳定来源键、原始 ID、父子关系、顺序、标题、正文定位及有依据的目标／时长。Bohrium 保留 category→chapter→entry，Velo 保留 modules→lessons；不将 entry 数当课时数。 |
| fields.lecture_notes | 课程正文资源数组：标题、对应课次／章节、本地已登记 documentPath、远端来源路径、格式、哈希。目录 JSON、README 和教材另标角色，不伪装成授课正文。 |
| fields.audience / level / prerequisites / learning_outcomes | 使用明确声明及可定位正文。没有明示的目标、先修课、学历层次不由难度或目录猜测。 |
| fields.duration | 保留数值、单位、范围、预计或实际属性；course.duration_hours 与逐讲 estimated_minutes 分别记录。字数、章节数不推算实际授课时长。 |
| fields.exercises / assessment | 习题题干、答案、检查点、验收方式按实际资料分开整理；自学思考题不等于正式考试和评分制度。 |
| fields.authors / institution / date / location | 只采集课程自身事实。教材作者、爬取者、文件 mtime、归档日期、模型名不自动映射到讲师、主办方和开课日期。 |
| fields.reading_list / related_books / related_papers | 分清建设依据、推荐阅读和百科关系；只用真实 ID 或资料明确给出的 DOI／URL，来源相同不等于主体相同。 |
| fields.example_codes / example_datasets / slides | 只登记明确配套资源及版本、位置；没有的填 not_found 或有依据的 not_applicable。不收集课程视频。 |
| fields.license / access_conditions | 区分课程、来源教材、代码和数据的许可；文件可读不等于允许公开分发，不凭文件类型填写开源许可。 |
| sections.course_background / key_topics / supporting_materials | 说明建设来源、测试／生成情况、知识结构和资源用途；JSON 中 software 混入的教材应识别为教材，不当科研软件。保留来源声明与本次核查结论的区别。 |
| sections.fusion_applications | 仅依据本课明确内容整理；不为了完整而给所有课程添加聚变应用。 |

structured value 本体遵循字段字典，证据和结果状态通过 submit_field 单独传递，不在每个业务值外套一层自定义 status/value 对象。工具 outcome 使用 verified、tentative、not_found、not_applicable、conflict、blocked；“verified”只指此次证据支持程度，不是课程学术认证。

证据使用真实 `documentPath` 或当前关联来源 `sourceId`、实际 URI、原文节选和可复查 locator（章节标题、行号、entry_id 或 JSON 路径）。网络 URL 只沿已批准来源核对身份、许可或资源位置，不扩展课程清单和教学内容。无法从允许资料支持的事实留空并记录原因；不得借一般知识补编前置要求、考核、主讲人或公式。

存在同一主体同一版本的未解决冲突时提交 conflict 和候选证据，保留原值；不同版本先区分，不能拼接成一门不存在的课程。Bohrium 自动生成关系、Velo 自报 QA 结论不能证明科学正确；保持来源限定，不为核验而自动重写课程。
