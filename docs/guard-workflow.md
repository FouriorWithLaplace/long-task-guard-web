# 守护业务说明

## 启动和使用

需要 Node.js 24、已安装并登录的本地 Codex，以及至少一个已有会话。

```powershell
npm install
npm run dev
```

打开终端显示的本地网址，然后：

1. 首页选择“新建守护”，选择已有会话，确认自动显示的工程目录。
2. 首次点击“更新模型”读取真实模型和支持的推理强度，之后打开页面只读缓存。
3. 填写开始、异常重试和正常结束后发送的消息。
4. 点击“开始守护”后创建独立守护记录并在原会话中执行，随后进入该守护详情。只填写配置或离开新建页面不会创建记录。
5. 正常结束后立即发送正常结束消息，意外中断后立即发送重试消息。
6. 点击“暂停”中断本轮执行，并取消下一次发送。再次开始会发送“开始时发送”的内容。

首页的“查看已有守护”进入卡片总览。每张卡片显示会话、模型、工程目录和实时消息窗口，点击卡片的标题或基本信息进入详情。卡片消息窗口可独立滚动；复选框和操作按钮不触发跳转。
总览支持全选和批量开始、暂停、删除，也可以单独开始或暂停。批量开始直接并发执行，不设置队列或并发上限。批量删除会先调用对应守护的暂停流程，完成后移除记录；不删除 Codex 会话或工程文件。
每个守护具有独立 ID、配置、连接、日志和授权请求。同一个会话可以被多个已暂停守护引用，但同时只能由一个执行中的守护占用；启动、续发、等待输入和暂停过程中均保持占用。冲突通过 API 返回 409。

对应的后续消息留空时，该分支结束后自动暂停，不会发送空消息。
运行记录显示真实计划步骤、简短进展和工具活动。读取文件、搜索代码、修改文件等操作在开始时显示“进行中”，结束后更新同一条记录的状态，不为开始和结束各加一条日志。
工具活动只保存概括和结果状态，命令、参数、命令输出和文件修改明细不进入运行记录。操作类型优先使用 Codex 的结构化字段，无法识别的命令显示“执行命令”，不推断它是否在测试。
计划只显示已开始或已完成的步骤；Codex 提供推理摘要时，只显示摘要的简短主题，不读取完整推理。文字概括取第一句、最多 160 个字符，不额外调用模型。
暂停、断线或本轮结束会结束仍在进行中的活动标记；缺少操作完成通知时显示“已结束”，不会据此宣称操作成功。
主动暂停不会触发中断重试。Codex 仍在内部自行重试时，本轮仍在执行，不叠加发送新的消息。
执行期间配置会锁定；Codex 实际请求授权或用户输入时，页面会显示操作控件。
沿用本地 Codex 的配置，不额外覆盖沙箱或自动同意授权请求。

刷新、切换页面或关闭网页不会取消服务器上的守护任务。所有守护记录、运行状态和每个守护最近 500 条日志保存在本地服务内存中，重启服务后会清空。
网页通过 SSE 保持一条连接，服务器在状态或日志变化时主动推送，不再每秒发送 GET 查询。断线后自动重新连接并接收最新状态，不会重复开始任务。连接保活和状态推送不会向 Codex 发送消息。
开始连接 Codex 时就会推送状态，AI 的简短进展随输出实时更新，无需等执行结束或点击暂停。开发热更新期间共享同一个多守护管理器。

## 模型缓存

模型目录长期保存在 `%LOCALAPPDATA%\LongTaskGuardWeb\model-catalog.json`，不自动过期。
只有点击“更新模型”才查询本地 Codex，失败时保留旧缓存。选中的模型和推理强度保存在浏览器本地存储中。

可选环境变量：

- `LONG_TASK_GUARD_CODEX_PATH`：本地 Codex 可执行文件的绝对路径。未配置时寻找 PATH 和 VS Code 插件中的原生可执行文件。
- `LONG_TASK_GUARD_DATA_DIR`：模型缓存目录。
- `CODEX_HOME`：沿用 Codex 自身的数据目录配置。

## 代码入口

- `src/app/page.tsx`：查看已有守护和新建守护两个入口。
- `src/app/guards/page.tsx`：卡片总览和批量操作。
- `src/components/GuardEditor.tsx`：新建与详情共用的会话选择、设置和操作页面。
- `src/components/GuardCard.tsx`：守护基本信息与实时消息窗口。
- `src/hooks/useGuards.ts`：总览和详情的实时状态订阅。
- `src/hooks/useGuard.ts`：页面接收实时状态、开始和暂停操作。
- `src/server/guard-runner.ts`：执行状态、事件触发续发、中断立即重试、暂停和日志。
- `src/server/guard-events.ts`：SSE 推送、断开清理和慢速读取时合并状态。
- `src/server/guard-manager.ts`：维护多个独立守护、检查会话占用、暂停后删除。
- `src/server/codex-client.ts`：本地 Codex app-server 的标准输入输出通信。
- `src/server/guard-service.ts`：验证会话和模型、创建和启动守护、批量操作。
- `src/app/api/guards/route.ts`：列出和创建守护。
- `src/app/api/guards/[id]/route.ts`：单守护读取、操作和删除。
- `src/app/api/guards/bulk/route.ts`：批量操作。
- `src/app/api/guards/events/route.ts`：接收所有守护状态和日志的长连接接口。

AI 和本机脚本可调用相同的 HTTP API，详见 [守护 API](./guard-api.md)。
