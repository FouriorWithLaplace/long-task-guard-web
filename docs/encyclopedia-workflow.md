# 百科采集工作台

首页 `/` 是八大分类入口：书籍、论文、期刊、装置、机构、人物、课程、科学词条。科学词条自动包含其他数据库子类型，分类规则与 FusionNexus 的知识导航对应。未删除的排除词条可查看，但不能启动。

分类列表每页 30 条，可按名称、英文名、ID 搜索。分类列表和任务列表均可选择默认排序（原始 ID 升序）、首字母排序（中文拼音 / 英文 A–Z）和完成度从高到低排序。完成度是已处理字段数占可处理字段数的比例，比例相同按 ID 排序；排序在分页之前进行。字段详情来自数据库固定列、逻辑类型表和字段字典，不把非空字段视为已经核实。点击字段展开原值、规则、核查理由、证据及下一次复核条件。已有来源与原件独立展示。

## 导出已完成词条

首页的“导出全部已完成词条”下载数据库和展示用图片 ZIP，不包含 PDF、讲义等原始资料文件。以导出开始时的当前任务状态为准，只选取 `completed` 且未删除的词条；包含已经检查但暂无法确认的字段。没有符合条件的词条时显示提示，不生成空包。

- `data/encyclopedia-workspace/encyclopedia.db`：保留主库全部表结构、索引、视图、触发器、字典、原始 ID 和字段值，以及所选词条的证据、修订等关联数据。
- 原件的数据库记录保留，但原件文件不读取、不校验、不打包。导出副本通过 `system_config` 标记原件未随包提供；源数据库不变。
- `data/encyclopedia-workspace/assets/...`：关联外置图片，保持 `relative_path`；旧版内嵌图片继续保存在数据库 BLOB 中。
- `manifest.json`、`README.txt` 和 `迁移指南.md`：词条 ID、数量、文件清单及使用说明。`迁移指南.md` 面向 AI，说明同结构工程的停服、备份、替换、校验和页面摘要重建步骤。请完整解压并保持目录结构。

跨词条关系仅保留两端均在导出库中的记录；未绑定采集输入、候选导入批次和整库运行报告保留空表。审核状态、可见性和维护库标记不变。网络链接保留原样，不额外抓取网站。

导出使用只读业务库快照，逐表抽取数据，不复制整个主库；构建过程中定期让出执行权。完成后检查数据库结构和外键，校验图片的大小与 SHA-256。图片缺失、损坏或路径越界会报错，清理临时文件，不返回残缺 ZIP。原件缺失不影响导出。

`POST /api/encyclopedia/export` 返回 HTTP 202 和 `{jobUrl}`，后台继续打包；页面轮询任务状态，失败原因保留在导出区域。接口默认且仅支持不含原件的展示包（也兼容 `?mode=display`）。任务完成返回 `{status: "ready", url, filename, count, originalsIncluded: false, expiresAt}`，页面尝试自动下载，并保留“下载 ZIP”链接。

`GET /api/encyclopedia/export/:token` 流式下载，不在浏览器内存中构建大文件。链接在生成后 10 分钟内可重复使用，下载中断可重试。到期或 `DELETE /api/encyclopedia/export/:token` 释放链接，已有下载继续传输，全部流关闭后清理临时目录。重新导出会先释放当前页面的旧链接。同时只允许一个生成任务，最多保留两个待下载文件。构建失败也会清理；进程被强制结束时，系统临时目录中可能留有 `encyclopedia-export-*`，可在服务停止后清理。

验证：`tests/encyclopedia-export.test.mjs` 覆盖结构与 ID、关联筛选、并发快照、原件和图片打包、损坏/缺失/越界、取消与下载清理，并在本机真实库可用时校验完整真实表结构。

每个分类页提供“下载字段表 · Markdown”按钮，下载该分类全部子类型的字段字典，不受当前搜索、分页和任务筛选影响。表格包含字段键、名称、分组、存储位置、逻辑类型、采集规则、是否允许自动填充和字段说明；身份字段及暂停采集字段也会列出并标为不可自动填充。

分类页的任务状态下拉框和卡片使用四种工作状态，筛选另含“全部”：未开始、进行中、已完成、完成部分。“未开始”表示本系统没有启动过任务，数据库原有内容不影响此判断；“进行中”包含排队、启动、执行、等待重试及正在停止；“已完成”表示所有可处理字段都已检查，不代表全部字段都有内容或均已核实；“完成部分”表示任务已启动但尚未完成且目前未运行，包括处理了 0 个字段就停止的情况。筛选先于分页，跨页全选采用相同分组。排队、重试、提交待核对等执行细节仍保留在任务说明中。

每个词条显示“已填充 X/N、已处理 Y/N”。总数只包含资料采集字段；身份和暂停采集字段保留只读展示，程序计算字段不显示在本任务详情中。资料字段保留原有核查结果规则：未找到、不适用、冲突及规则限制也是已确认的处理结果；已有内容不等于已经核查。程序字段保留在数据库及字段字典中，供后续统一索引和计算，但不属于 Codex 采集任务、统计或详情展示。

页面更新器跟踪百科数据库和任务状态文件的变更日志及文件替换，自动重新对齐范围、当前值和完成状态；字段定义变化会重新核对相关任务。对齐保留历史字段结果和证据，不启动任何任务；运行中或存在未确认提交的任务由执行器核对，避免覆盖并发写入。停止的任务全部条件满足后可以重新标为完成；已完成任务缺少新的资料字段或资料字段实值发生变化时返回“完成部分”。页面摘要格式升级为 5，更新器重启后自动重建旧版进度，剔除程序计算字段。需要手动全量对齐时，在页面更新器停止后执行 `node scripts/page-views.mjs --once --rebuild`，随后正常启动服务。

勾选单条或“全选本页”后，可进一步“全选符合条件的词条（跨页）”。跨页选择保存当时匹配的 ID 快照，后续新增匹配项不会自动加入。翻页保留选择，更换分类、搜索条件或任务状态清空选择。批量开始、重新开始、停止一次提交全部选中 ID（最多 50,000 条），页面显示成功、跳过、失败及逐条原因。后台用一次事务保存整批意图；成功表示已接受，执行及会话清理进度由任务状态显示。请求中断不盲目重发，刷新任务状态后再处理未确认项。

批量开始跳过已完成项，并使用页面所选模型和推理强度。新任务默认使用 `gpt-6-astra / medium`；未显式传入设置的 API 请求保留已有任务设置。已在执行或排队的词条跳过，不重复启动，也不在运行中重置进度。批量请求中单个 ID 的参数错误不阻止提交其他 ID；实际执行遵循全局并发上限，其余排队，执行失败的词条保留自己的名额重试。

一次批量开始（继续执行）由后台对全部选中 ID 按完成度从高到低排序，未开始视为 0%，比例相同时按 ID 升序。排序与页面展示顺序无关。`POST /api/encyclopedia/batch/order` 仍可单独预览顺序，页面无需先调用它。入队只检查词条身份、状态和设置参数，不查询模型目录，不读取完整字段、证据，不保存规则快照或创建 Codex 连接；取得执行名额后才做这些准备。字段规则或模型可用性问题在实际执行状态中报告。入队序号持久化，防止同一毫秒内的入队次序在调度或服务重启后被 ID 顺序覆盖。已有运行和排队任务保持原安排；批量重新开始、停止、修改模型不采用这个继续执行排序规则。

页面上方的“同时执行词条数”控制所有分类共享的执行上限，默认 2，接受正整数并保存到任务库，重启后保留。调高立即安排更多排队任务；调低不打断现有执行，直到占用名额少于新上限才补任务。`GET /api/encyclopedia/settings` 返回 `{concurrency}`，`POST` 同路径保存 `{concurrency: N}`。调低时页面可能暂时显示超过新上限的运行任务，这是现有任务自然结束前的正常状态。

分类页、运行任务页和详情页直接显示“模型与推理强度”。选择 `high` 等强度后，点击“应用模型到所选任务”或详情页“应用到当前任务”保存到已有任务。运行中从下一轮请求生效，当前请求不被中断；保留进度、会话和运行意图，已停止的任务不会自动开始。设置在任务库中持久化；浏览器另行记住下次开始使用的选择，不沿用旧版通用守护页的 low 偏好。

单条和批量接口都支持 `action: "configure"`，例如向 `/api/encyclopedia/batch` POST `{ "action": "configure", "ids": [1,2], "model": "gpt-6-astra", "reasoning": "high" }`。`continue`、`restart` 也接受 `model` 和 `reasoning`。模型及推理强度必须存在于本地模型目录；不可用时返回错误。修改设置不会创建尚未开始的任务，正在停止的任务需等停止结束后再修改。

## 每个词条的生命周期

每个词条只有一份当前任务状态和最新字段结果，没有轮次编号或每轮快照。同一词条最多一个执行，同时执行数量由全局设置控制，多余任务按入队时间等待。页面关闭不停止本地服务中的工作；服务必须保持运行。

- **开始**：未开始的词条新建任务；有工作记录的词条只续做尚未检查的字段。停止后再次开始会新建 Codex 会话，沿用已保存进度。查无资料的字段不重复搜索。已完成词条禁用“开始”。
- **重新开始**：已有任务可重新处理全部字段，保留数据库现值和最新证据，将所有可处理字段重新列为待处理，已处理计数归零。使用新的执行标识隔离旧回调，不创建历史轮次。旧字段结果显示为最近核查结果，不算新任务已处理。
- **停止**：停止当前执行及重试，删除当前 Codex 会话，保留已确认的字段结果。未完成时归入“完成部分”，全部字段已确认则归入“已完成”。没有暂停按钮或保留会话后继续的操作。
- 两种开始方式执行相同的查证、纠错和补充流程，仅处理范围不同。运行中需先停止，才能重新开始。

执行失败持续重试，不设置次数上限。等待间隔为 5、10、20、40 秒，此后最多 60 秒；重试等待期间保留名额，不让排队词条顶替，其他名额独立推进。连接初始化、会话创建和提交核对失败也重试。请求过大、上下文失效或会话丢失会清理旧会话并新建。Codex 内部正在重连时不叠加续发。只有任务完成或用户停止才交出名额。

回复结束不等于任务完成。只有范围内所有字段都有已确认结果、实库值与记录匹配、没有未确认提交，才能完成。未完成则自动发送剩余任务；连续三次回复没有新增字段结果时更换会话并继续重试，保留名额和成果。查无资料属于字段结果，不属于执行失败。提交不明时持续核对审计与实库，确认前不重复写入。

用户停止时，先持久化停止意图并拒绝迟到提交，接口立即返回已接受；整批停止意图保存后才在后台中断、核对事务、删除会话，释放执行名额。未执行且无待核对记录的排队项直接停止，不创建清理连接。正在执行的任务保持“正在停止”直到清理结束。最多等待在途创建或开始响应 5 秒；超时关闭执行连接并通过独立连接删除已知会话，迟到的会话 ID 也只进入清理，不会重新执行。提交核对失败不会阻止会话删除，写入意图保留以便后续核对。删除失败显示待清理列表，再次停止、开始或重启服务时重试清理，不伪称删除成功。

服务启动由 `src/instrumentation.ts` 初始化管理器，读取持久状态。30 秒服务租约避免多个服务实例同时执行；运行或重试任务恢复原名额，未执行任务继续排队，主动停止的任务保持停止。恢复先核对修改审计和实值，不盲目重放提交。

首次更新需重启本地服务。取得租约后，在事务中将旧轮次的字段结果合并为每字段最新结果，再删除 `rounds` 表和轮次属性。保留写入核对记录、证据和研究笔记；旧协议会话转入待清理列表，后续执行使用新工具协议。旧暂停记录转换为停止并删除保留会话，进度保留，不自动启动。存在未确认提交时不能重置任务，需先继续核对旧提交。

开发热更新可能保留旧后台实例。页面兼容缺少 `processedFields` 的旧任务，根据已确认结果展示处理进度；无法取得填充数量时显示“—”，不推测为零。新任务显式保存的空进度不会被旧结果恢复。旧后台仍可停止，但开始和重新开始会提示重启服务，避免使用旧版执行语义。

## 技能与写入

规则源：`skills/encyclopedia-collect/SKILL.md`。任务绑定按 SHA 去重的技能快照；继续沿用原规则，重新处理全部字段时采用当前规则。

课程分类按 [课程整理与填充规则](course-reconciliation-rules.md) 收录 Bohrium 和 Velo 两批共 12 门有 Markdown 正文的完整课程。新增、软删除和原件登记是独立目录维护阶段，当前单词条工具不提供这些能力；完成后再由工作台填字段。课程专项采集规则已内嵌于 SKILL.md，随规则快照加载。更新技能后需重启服务读取新规则；已有任务需要“重新开始”才采用新版快照。

采集会话使用只读沙箱，通过网络检索及已登记本地资料研究。动态工具：

- `entry_context`：现值、规则、原件、既有证据；每批最多八个字段，避免上下文无限增大。
- `entry_source`：校验并分页读取已有来源快照。
- `submit_field`：逐字段提交研究结果，服务器决定能否采用。
- `save_note`：在当前任务独占目录保存笔记。
- `finish_task`：请求程序执行完成检查。

写入器核对词条、字段、旧值、版本、规则、证据与来源关联；不允许改名、身份字段、规则暂停字段或已排除词条。不清空已有有效值；没有资料时记录原因并保留现值。字段规则缺失或事实语义仍需采集模型判断，结构检查不能证明事实正确，暂定值及来源冲突须人工可见。

写前把意图与旧快照保存到启用 FULL 同步的任务库，再取得业务提交结果。共享门禁为 `data_root/encyclopedia-sources/.fixed-task-writer.sqlite`。业务事务合并基线，保留固定列已有扩展信息，追加来源、审计、正文版本和修订，设为待审核且不可公开；由既有触发器同步固定列和值类型。提交后独立回读。提交不明时根据同一事务内的审计指纹核对，不依据一次错误响应猜测是否成功。

## 本地记录

```text
encyclopedia-agent/
  panel/
    state.sqlite            # 每词条当前状态、最新结果、写入意图、事件和服务租约
    rules/<SHA>.md          # 按内容去重的技能快照
    notes/<词条ID>/<run_id>/ # 持久研究笔记
  tmp/<词条ID>/<run_id>/     # 执行环境临时目录
```

每词条当前状态只有一行；证据和历史会随实际工作增长。会话删除不删除这些记录。不要在服务运行时直接复制 SQLite 主文件而遗漏 WAL，也不要删除未确认意图或证据。

业务 API 位于 `/api/encyclopedia/`：`categories`、`categories/:key`、`categories/:key/fields`、`entries/:id`、`tasks`、`events`、`batch`、`entries/:id/terminal`。`GET categories/:key/fields` 返回 `text/markdown` 附件。对词条 POST `{ "action": "continue", "model": "缓存模型ID", "reasoning": "high" }`（页面“开始”），或将 action 设为 `restart`（重新开始）、`stop`。不接受旧 `start` 和 `pause` 操作。分类 GET 支持 `q`、`page`、`status`（`all|never|running|completed|partial`），添加 `selection=all` 返回相同筛选下的全部 ID。批量 POST `/batch` 接收 `{ "action": "continue|restart|stop", "ids": [1,2] }`，每次最多 50,000 条并去重，返回每条 ID 的 `success|skipped|failed` 及原因。读取接口不创建采集任务。终端复用现有只读 PTY/SSE 技术。
